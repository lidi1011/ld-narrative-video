# 制作流程

本流程服务于一条可修改、可核对的横屏或竖屏叙事视频。它描述阶段之间的输入和输出，不把阶段顺序变成额外审批门；用户已授权的连续工作可以直接执行，用户指定的停止阶段优先。

## 1. 建立任务边界

先从上下文和现有文件确定观众、目标、主题、交付阶段、画幅、声音选择和素材来源。已有配置继续沿用，只询问会明显改变结果且无法合理推断的缺口。没有 IP、品牌或配音需求时，不为了凑齐目录而创建对应资产。

新任务按需建立以下入口：

```text
<new-task-root>/
├── BRIEF.md
├── HANDOFF.md
├── inputs/
├── video/
└── delivery/
```

项目提供的初始化命令是：

```bash
python3 <skill>/scripts/create_project.py <new-task-root> --title '主题'
```

`BRIEF.md` 记录目标、受众、交付阶段、约束和已知决策；`HANDOFF.md` 记录当前完成度、可复现命令、实际验证和未决项。`inputs/` 只登记真实收到或明确可访问的素材，并保留来源和版本线索。

## 2. 内容与素材登记

入口可以是定稿、已有配音、主题/资料、录屏、实拍或这些内容的组合：

- 定稿直接进入时间和分镜，旁白文字不得在制作阶段被润色、扩写或缩写。
- 主题或文章需要形成脚本时，先区分资料中的事实、创作性表达和待核查内容；新增写作应明确标注为本次创作。
- 已有配音或素材原声先登记媒体、保留片段、内容版本和是否保留原声；需要补充画面时围绕它编排。
- 明确无声时按阅读节奏和信息展开安排时间，不创建 TTS、占位音频或无来源 BGM。

常规输出为 `video/script/story.md`、旁白需要时的 `narration.txt` 和素材清单。时间轴、分镜、素材字段的根结构和验收约束以 [`contracts-and-qc.md`](contracts-and-qc.md) 为准。

## 3. 形成时间依据

所有镜头最终共用一条成片时间坐标。选择与输入相符的分支：

1. 有已对齐旁白时沿用测量结果，并记录静音间隙。
2. 有已有配音但没有时间信息时，跳过合成，使用项目提供的对齐工具，并保留实际音频和差异报告。默认 TTS 由音频适配器 使用豆包适配；连接信息与配置遵守用户授予的唯一授权，不在通用技能中复制路径、密钥或其他项目的适配器。
3. 使用素材原声时保存源媒体起止与成片位置映射，剪切后同步更新字幕和镜头事件。
4. 无声任务按内容阅读和变化节奏建立事件，不伪造语音时长。

需要 TTS 或对齐时再读取项目的 `references/audio-tools.md`。整篇声音、对齐和字幕文本要指向同一内容版本；ASR 只提供时间线索，不能用识别结果偷偷改写定稿。

## 4. 设计分镜

分镜从“观众在这一段要理解什么”开始，然后决定镜头职责、表现模块、配方、素材、关键画面和变化点。每个镜头至少能回答：

- 画面最终要呈现什么，以及它在时间中如何形成或改变；
- 使用哪份真实素材、示意图或代码图形，缺失时如何标记；
- 旁白或原声的哪个事件触发变化；
- 过渡、实现方式和可能的验证点是什么。

以 `script/shots.json` 为唯一可编辑源，使用：

```bash
python3 <skill>/scripts/build_storyboard.py --project-root <video>
```

它应由同一份数据生成 `shots.md` 和 `index.html`。`--capture` 抽帧来自真实 HTML 工程；概念草图只能讨论方向，不能充当交付关键帧。选择 `recipe_id` 时读取 [`shot-recipes.md`](shot-recipes.md)，选中模块时只读取对应的 `references/modules/*.md`。

不要把 A-roll/B-roll 当成镜头的固定分类，也不要把 IP 角色当作所有镜头的默认主角。一个镜头可以由录屏加文字标注、信息图加素材、IP 加流程图或多个模块叠加组成。

## 5. 实现样片与全片

先选能代表主要视觉关系和运动变化的镜头，在真实 HyperFrames 工程中实现，再从工程预览检查关键帧和短片。样片通过后，沿用已经验证的 `DESIGN.md`、布局和模块组合完成剩余镜头；只修受影响的镜头和资产。

当前项目已验证 HyperFrames 0.8.35，优先运行项目自身的 `npm run check`、`npm run dev` 和 `npm run render`。需要快照时使用原生 snapshot 命令的 `--at` 指定时间，并传 `--describe false`，避免自动调用外部描述服务。无论使用 npm script 还是底层命令，先读 `package.json` 和实际 `--help`，确认后再执行；技能不猜测参数、不承诺尚未验证的浏览器或媒体选项。

渲染前检查中文字体、图片、音频和混合镜头是否都能在独立项目内解析。

## 6. 检查、交付与修改

按项目的 `contracts-and-qc.md` 检查时间、文本、画面、声音、文件和来源。媒体存在时可运行：

```bash
python3 <skill>/scripts/check_project.py --project-root <video> --media renders/final.mp4
```

再用 `ffprobe` 和实际播放/抽帧确认流、尺寸、帧率、时长、解码和画面信息。检查报告只陈述真实执行的结果；不能以“格式校验通过”代替视觉、听感或产品真实性检查。把工程、成片、字幕、来源记录和 `HANDOFF.md` 一起交付，确保它们指向同一个内容和资产版本。

修改时按影响范围重做：

- 只改颜色、排版或图片层，不触发 TTS，但要重新检查受影响镜头和成片。
- 改旁白、定稿或配音，要把旧对齐、字幕和相关镜头标为待更新，并重新生成受影响部分。
- 改录屏、实拍片段或角色动作，只替换依赖该资产的镜头；检查剪切连续性和来源。
