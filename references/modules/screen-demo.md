# `screen-demo` 屏幕演示模块

## 何时加载

当镜头要展示真实网页、应用、软件工具或操作结果时加载。它最常与 `focus` 配方组合，也可以叠加 `steps`、`comparison` 和 `typography`。

## 输入与准备

登记实际截图或录屏的来源、应用/网站版本、采集时间、状态、保留片段和原声选择。先确认要证明的是哪个操作或结果，再决定全屏、裁切、局部放大、光标、描边和文字标注。产品名、按钮、数据和结果必须来自可访问的真实材料。

没有真实操作材料时可以制作界面示意，但在画面或交付记录中明确标为“示意”“概念”或“待实测”；不能用虚构的 UI、账户、数据或成功状态冒充功能证据。隐私信息按任务范围处理并记录素材版本，避免把无关敏感数据带进成片。

## 实现提示

先建立整体界面上下文，再依事件聚焦目标区域，展示实际操作/状态变化和结果。放大框、光标轨迹、遮罩和重点标注属于解释层，不能替代缺失的点击、输入或结果。录屏与旁白共用成片时间轴；按原声交付时不要默认替换音轨。

`build_storyboard.py --capture` 若在当前项目已实现，只能从真实 HTML 工程抽帧并生成联系表；它不把截图或概念图转换成真实产品操作。HyperFrames 的预览、渲染参数以项目 npm scripts 和实际 `--help` 为准。

## 质量检查

- 版本、状态、步骤和结果与真实材料一致；
- 关键控件、文字、光标和放大区域在所选画幅实际尺寸下可读；
- 标注没有遮住要展示的操作或结果；
- 录屏剪切不产生跳帧、错误状态或无依据的连续动作；
- 原声、字幕和操作时间一致；
- 示意画面有明确标签，无法验证的结果没有写成已完成。

屏幕演示模块负责真实界面素材与解释层，不替项目决定全片风格，也不负责生成未提供的产品数据。
