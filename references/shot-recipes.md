# 镜头配方

配方描述一段信息如何在时间中变化。它们可以独立组成纯图解，也可以叠加到录屏、实拍、IP 或真人镜头上。配方不规定风格、布局、引擎或 A/B 分类；选择依据是观众要理解的关系、可用素材和当前镜头职责。

分镜中的 `recipe_id` 使用以下稳定 ID：`comparison`、`steps`、`grouping`、`cause`、`focus`、`takeaway`。根字段和事件合同以 [`contracts-and-qc.md`](contracts-and-qc.md) 为准。

## 选择方法

先写出一句镜头目的，再问“必须看见什么变化才能理解它”。如果答案是同一维度的差异，使用 `comparison`；如果是按次序完成，使用 `steps`；如果是归属关系，使用 `grouping`；如果是触发关系，使用 `cause`；如果要从整体定位到界面局部，使用 `focus`；如果要让概念或结论落定，使用 `takeaway`。

一个镜头可以使用一个主配方加一个补充层，也可以在连续镜头中组合多个配方。不要为了填满画面强行加入角色、图表或装饰。配方写的是可验证的信息变化，不是“酷炫”效果清单。

## `comparison`：对比

适合人工/自动、方案 A/B、前后状态、成本/收益等相同维度的比较。

必须发生的变化：两侧或两个时段以一致的比较维度出现，随后明确指出差异与结论。先建立共同参照，再强化关键差异；不要只把两张卡并排却不给比较关系。

可用表现模块：`infographic`、`typography`、`screen-demo`、`footage`，也可以由 `ip-character` 或 `presenter` 引出。

建议事件顺序：共同标题/指标 → 第一状态 → 第二状态 → 差异强调 → 适用边界或结论。

检查：两侧的单位、时间范围和视觉尺度一致；数据有来源；颜色和位置没有让“装饰更醒目”误导判断；语音说到的差异在对应时点可见。

## `steps`：步骤

适合操作教程、实现路径、准备到交付的顺序说明。

必须发生的变化：步骤按口播或时间依据依次出现，并在末尾到达可识别的结果。每一步要说明动作、对象和完成状态，不用一个“流程图已出现”代替真实推进。

可用表现模块：`screen-demo`、`infographic`、`typography`、`footage`，需要主持提示时再叠加 `ip-character` 或 `presenter`。

建议事件顺序：起点/输入 → 当前步骤高亮 → 动作或局部变化 → 步骤完成 → 下一步 → 结果/出口。

检查：顺序和旁白一致；录屏中的操作确实发生；步骤编号、光标、放大框或标注没有遮住关键控件；缺少真实输入时使用示意并清楚标注。

## `grouping`：聚合/分类

适合资料整理、知识结构、类型归属和“多个元素汇入少数类别”的解释。

必须发生的变化：元素从未归类状态进入明确组别，组的名称和归属关系在结束时仍可读。数量变化或结果状态要来自真实数据；虚构文件、图片和统计不能被呈现成真实扫描结果。

可用表现模块：`infographic`、`typography`、`screen-demo`、`footage`。

建议事件顺序：元素集合出现 → 分类规则提示 → 元素逐个/分批归组 → 组内结果稳定 → 数量或结论落定。

检查：每个元素有唯一且可理解的归属；连线、容器和颜色不相互冲突；分类规则和例外被说明；画面变化跟随事件，避免一开始就显示最终结果。

## `cause`：因果

适合解释机制、问题成因、触发条件和结果链条。

必须发生的变化：前因、机制或中间条件先出现，随后触发结果，箭头、时间顺序或状态变化明确表达关系。相关不等于因果，若资料只支持相关，应改写镜头表述。

可用表现模块：`infographic`、`footage`、`typography`、`screen-demo`；`ip-character` 可呈现情境，但不能替代事实依据。

建议事件顺序：问题/条件 → 机制或中间步骤 → 触发点 → 结果 → 限制、例外或行动建议。

检查：因果方向没有被布局反转；每一条关系都能回到文案或来源；动画在触发后才显示后果；不把示意箭头写成产品已验证功能。

## `focus`：界面聚焦

适合真实产品、网页、应用、录屏或截图中从整体定位到某处操作、结果的说明。

必须发生的变化：先建立界面或场景整体位置，再聚焦目标区域，随后展示真实操作或结果。局部放大、描边和光标是解释层，不能代替未发生的操作。

可用表现模块：`screen-demo` 为主，配合 `typography`、`infographic` 或 `presenter`。

建议事件顺序：整体上下文 → 目标区域定位 → 操作/状态变化 → 结果或下一步 → 返回整体或收束。

检查：录屏/截图版本和实际功能一致；文本、按钮、光标和放大框清晰；数据、账户和隐私信息按任务要求处理；模拟画面必须标为示意，不伪造成功结果。

## `takeaway`：结论强调

适合章节收束、核心概念、金句、决策建议和最后行动指引。

必须发生的变化：上下文先退居背景，关键词按层级出现，最后结论在足够停留时间内稳定可读。它不是把整段旁白全部放大，而是将已被前文支撑的结论收束出来。

可用表现模块：`typography`、`infographic`、`footage`，可选 `ip-character` 或 `presenter` 作为表达锚点。

建议事件顺序：上下文/问题 → 关键词或证据回顾 → 结论出现 → 重点强调 → 留出阅读/行动时间。

检查：文字与定稿一致；强调不改变原意；背景、音乐和动效不抢结论；最后画面有明确的停留和结束边界。
